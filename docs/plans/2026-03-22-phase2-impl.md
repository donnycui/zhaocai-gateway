# Phase 2 Implementation — 2026-03-22

## What Was Delivered

### 1. Responses API (`POST /v1/responses`)

New files: `responses/__init__.py`, `responses/handler.py`

- Accepts OpenAI Responses API format requests
- Converts `input` (string or message array) + `instructions` into chat messages
- Reuses `GatewayServer.chat_completion()` for routing, retry, and provider fallback
- Returns Responses API format envelope (`id`, `object`, `output`, `usage`)
- Streaming supported via synthetic SSE (`response.created` / `response.output_text.delta` / `response.completed`)

**v1 limitations:**
- Text input only (no file, image, multimodal)
- No tool use (function calling, code_interpreter, file_search)
- Stream is synthetic (full upstream call, then SSE emit)

### 2. GPT-5.4 Routing Foundation

- Added `"gpt-5"` to `CHAT_INCLUDE_KEYWORDS` in `control_plane/router.py`
- No hardcoded if/else — routing is entirely through the existing model alias system
- GPT-5.4 variants (`gpt-5.4`, `gpt-5.4-xhigh`, `gpt-5.4-general`) are configured via the control plane

### 3. OpenRouter Free Model Sync

New file: `scripts/sync_openrouter_free.py`
New endpoint: `POST /control/v1/sync/openrouter-free`
New store method: `upsert_model_by_alias()`

Sync logic:
1. Fetch `https://openrouter.ai/api/v1/models`
2. Filter models where `pricing.prompt == 0` and `pricing.completion == 0`
3. Score each model considering:
   - **Context window size** (128K+ = 30pts, 32K+ = 20pts, 8K+ = 10pts)
   - **Vendor reputation** (google, meta, deepseek, qwen, etc. = 20pts)
   - **Reasoning capability** (name contains "reason" or ends with "r1" = 15pts)
   - **Model size** (100B+ params = 10pts, 30B+ = 5pts)
4. Classify each model into categories (general, code, fast, reasoning)
5. Assign stable aliases:
   - `openrouter/free/best` — highest composite score
   - `openrouter/free/general` — best general chat (second highest, different from best)
   - `openrouter/free/code` — best coding model (name contains code/coder)
   - `openrouter/free/fast` — fastest (small model, moderate context)
6. Upsert via `store.upsert_model_by_alias()` — existing aliases get updated, new ones created
